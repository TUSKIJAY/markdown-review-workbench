# 优化点记录 SOP

> 本文件是 `docs/optimization/` 的事实来源。
> 一句话方针：先记录、编号、归档；只有用户明确要求实施时，才进入源码修改。

## 0. 这套流程解决什么

Markdown / Word 文档审阅标注工作台后续会持续优化阅读体验、标注流程、
Word 预览、导出格式、绿色版验收等细节。优化想法如果直接散在聊天里，
很容易丢失上下文，也容易出现“边看边改、没有验收记录”的问题。

本流程把优化工作拆成两步：

1. 记录阶段：只写文档，给优化点编号、描述现状和期望。
2. 实施阶段：用户明确要求后，再按编号改代码、验证、记录结果。

## 1. 何时触发

命中以下任一情形，走本 SOP：

- 用户提出优化建议、体验问题，并希望“记下来”或“收录一下”。
- 本地验收过程中发现阅读、标注、导出、同步、绿色版体验问题。
- 用户提供截图或描述某处不理想，但没有明确要求马上修改。
- 需要把一批优化点整理成后续实施清单。

不适用：

- 用户明确说“现在就改”“实施 OPT-xxx”“把这个修掉”。
- 阻断性 bug 或数据可靠性问题，需要立即修复。
- 已经进入某个明确开发任务的执行阶段。

拿不准是记录还是实施时，默认先记录，并在回复里说明“未改代码”。

## 2. record-only 红线

进入优化收集阶段后，在用户明确要求实施前：

- 只允许编辑 `docs/optimization/` 下的清单、SOP、截图或验收记录。
- 不修改 `src/` 下任何应用代码。
- 不运行会改变依赖、构建产物、数据库或打包结果的命令。
- 不顺手改小问题；再小的代码调整也等实施阶段。
- 不把优化点散落到 `docs/` 根目录或其他无关目录。

退出记录阶段的唯一方式：用户明确要求实施某条或某批优化点。

## 3. 目录结构

```text
docs/optimization/
├── SOP.md
├── template-优化清单.md          # 批次总索引，不要覆盖重建
└── YYYY-MM-DD/
    ├── YYYY-MM-DD-优化清单.md
    ├── YYYY-MM-DD-验收.md        # 可选，实施后补
    └── screenshots/
        ├── OPT-001.png
        └── OPT-002-1.png
```

规则：

- 每个日期批次一个目录，格式 `YYYY-MM-DD`。
- 当天多次收集并入同一批次。
- `template-优化清单.md` 名字里带 template，但在本项目中承担“总索引”作用。
- 有截图时必须保存真实图片文件，并在 Markdown 中引用。

## 4. 编号规则

- 每个日期批次内从 `OPT-001` 起。
- 批次内连续递增，不复用编号。
- 跨批次引用写 `YYYY-MM-DD/OPT-001`。
- 同一模块的相近问题可以合并为一个编号，在明细中分点描述。
- 截图按编号命名：`OPT-001.png`；多图用 `OPT-001-1.png`、`OPT-001-2.png`。

## 5. 记录步骤

1. 确认或创建当天目录：`docs/optimization/YYYY-MM-DD/`。
2. 确认或创建清单：`YYYY-MM-DD-优化清单.md`。
3. 分配下一个 `OPT-NNN` 编号。
4. 在概览表新增一行，写清标题、模块、状态和备注。
5. 在明细区新增对应章节，写“现状 / 期望 / 影响 / 截图 / 状态”。
6. 如有截图，保存到同级 `screenshots/`，并在明细中内联引用。
7. 更新 `template-优化清单.md` 的批次索引。
8. 收尾说明记录位置、编号范围，并明确未改代码。

## 6. 截图规则

- 不写指向不存在文件的图片引用。
- 每个 Markdown 图片引用都必须能在 `screenshots/` 找到同名文件。
- `screenshots/` 里的每个优化截图都应被清单引用。
- 拿不到截图文件时，写“截图待补”，不要伪造路径。

## 7. 状态词表

| 状态 | 含义 |
|---|---|
| 待确认 | 已记录，等待用户确认是否实施 |
| 进行中 | 已确认，正在实施 |
| 已完成 | 已实施并验收通过 |
| 搁置 | 暂不做或延后 |

## 8. 清单模板

新建当批 `YYYY-MM-DD-优化清单.md` 时使用：

```markdown
# 优化点清单 · YYYY-MM-DD

> 本批次记录 YYYY-MM-DD 发现的 Markdown 阅读器优化点。
> 先收集、后确认、再实施。截图放在 `screenshots/`。

**集中模块**：<文档预览 / 标注面板 / 导出 / Word 预览 / 绿色版 / 待定>

> **实施进度（YYYY-MM-DD）**：收集中。

| 编号 | 标题 | 涉及模块 | 截图 | 状态 | 备注 |
|---|---|---|---|---|---|
| OPT-001 | <一句话标题> | <模块> | 无 | 待确认 | <要点> |

---

## 明细

### OPT-001 <标题>

- **涉及模块**：<具体页面/组件/流程>
- **现状**：<现在怎样，问题在哪>
- **期望**：<希望优化成怎样>
- **影响**：<影响阅读效率、标注准确性、导出可靠性等>
- **截图**：无
- **状态**：待确认
```

## 9. 收尾话术

记录阶段收尾时说明：

```text
已记录 N 条优化点到 docs/optimization/YYYY-MM-DD/YYYY-MM-DD-优化清单.md。
本次只做记录，未改任何应用代码。需要实施其中某条，请指定编号。
```
